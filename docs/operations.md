# Runtime and harness operations

Download the root frontdoor once and run `& ./install.ps1` locally for the latest stable installation/update, then `& ./install.ps1 -Mode Verify`. Optional Check/exact-tag controls are documented in README. The actual Windows user, an owned operation WorkRoot and existing Python/harness inputs are automatic. Keep the actual service root, port and private broker.env. Relative DB/log/audit paths belong to the selected runtime cwd; code resources belong to the package. Generic loopback defaults are not authority to replace provisioned settings.

An auto-selected installed harness with unavailable prerequisites blocks the complete preflight; it is not silently omitted. A fresh operator may deliberately narrow to `-Harness @('claude','codex')`, another supported subset, or `-Harness @('none')` while resolving the unavailable adapter. Existing selections remain retained on upgrade. Legacy Python comes from the declared pyvenv.cfg home/python.exe with matching optional executable metadata and actual base/version/path/prefix checks; inconsistent aliases or missing bases are prerequisites, not fallback authority.

Claude registers `local-relay-channel` with the installed venv Python and plugin server on a fresh install. A correct adopted registration using the explicitly selected base Python is retained after its actual MCP dependencies are checked. The library resolves through the retained same-user hooks junction when present; no receive hooks or enterprise policy is installed. Launch its documented channel wrapper explicitly only when using that feature. A foreign registration refuses. The nonsecret connection.json selects the retained loopback port unless an explicit matching BROKER_BASE_URL is configured.

Codex uses the installed PowerShell 7 session launcher with explicit BrokerDirectory, StateDirectory, WorkingDirectory and SessionKey. Preserve exact state/session coordinates on resume. The short wrapper never searches a hidden second root or forces a private model. Its eleven overrides register `relay` only for that session, not globally.

OMP selection contributes `omp-relay` and the selected extension to the actual agent directory returned by its public `config path` API, respecting current profile/agent environment selection on first install and retained verified coordinates thereafter. No mandatory named profile or coordinate matrix is required. Use mounted `mcp__omp_relay_send`, `mcp__omp_relay_check`, `mcp__omp_relay_name` tools; do not infer a Claude session ID, run a Codex launcher or call raw HTTP as an alternate identity. Native results/errors retain their meaning. The base-Python guard remains; existing relay state/runtime roots and foreign/disabled registrations cannot be silently replaced during adoption.

Use a fresh selected-harness session against an owned disposable broker to prove actual MCP initialize/tools-list/read-only behavior. Neither installation, parser support, historical evidence nor a production port's response is such proof. Activation/autostart/notification enablement always require separate authorization.
